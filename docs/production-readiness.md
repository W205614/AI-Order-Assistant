# 上线准入与运行边界

本项目的交付范围是校园多商户试运营，不以“大厂同款”作为验收标准。工程实现、本地测试、生产实联和运营接管分别完成后，才能决定正式放量。没有测试可以证明以后只需修改业务、不再需要安全更新或故障修复。

当前工程与本地结果见[实现验收](verification/2026-11-06.md)及[整改与日常部署收尾](verification/2026-11-06-production-closeout.md)，此前代码／远端／容器快照见[上线核对](verification/2026-11-06-readiness-audit.md)。本文列出长期准入条件，快照状态须在每次发布时重查。

## 启用前必须完成

| 项目 | 完成条件 | 留存证据 |
|---|---|---|
| 源码发布 | 已审阅变更提交并同步到目标分支；本次CI与安全检查通过 | 提交号、CI链接、扫描回执 |
| 应用身份 | 使用该版本构建的固定镜像；实际容器与镜像摘要相符，迁移成功、健康及角色验收通过 | 发布回执、镜像摘要、迁移与HTTP结果 |
| 微信与商户 | 服务商／逐商户授权、产品权限、公众号域名；Native、H5、JSAPI、回调、关闭、退款和已出账对账通过 | 渠道和本地单据对照、差异处理记录 |
| 短信、图片与地图 | 自有手机号收码绑定／找回、私有OSS存取与授权、高德地址和路线实际通过；未使用的能力明确关闭 | 脱敏生产验收报告 |
| 云数据与公网 | 真实MySQL／Redis TLS及最小权限、域名证书、网络出口、密钥轮换方式通过 | 实例／身份脱敏标识、TLS及权限结果 |
| 告警与值守 | 生产接收端实际收到触发和恢复；支付未知、退款积压、对账差异有处理负责人 | 收件时间、值守与升级联系人 |
| 备份与恢复 | 独立生产备份策略、异地回读摘要和独立恢复；核验新增资金、身份、媒体与通知数据 | 备份摘要、独立恢复及对象回读报告 |
| 业务与AI | 正式角色走完整交易；若启用模型，在实际额度下完成模型验收；容量符合实际试点负载 | 浏览器与数据不变量、模型及负载报告 |
| 运营接管 | 商户收款及优惠承担、售后与配送异常处理、私密漏洞联系渠道及数据处理责任明确 | 运营配置和负责人确认 |

未启用的可选服务不应假装接入成功；例如关闭AI时仍可使用普通点餐。决定上线范围后，对启用能力逐项验收，不能用默认脚本的`NOT_RUN`或配置可读取作为通过。

## 恢复验收与发布门禁

`restore-db.ps1`默认执行integration模式，在独立、无外部网络的MySQL中导入SQL，检查V1–V9业务表的全列有序SHA-256指纹，以及支付、退款、商户绑定、OAuth、手机号、媒体和通知的归属与金额不变量。显式`-CampusSchema`／`-SchemaMode legacy`只用于旧结构恢复，不能作为新版发布证据。

新版发布要求schemaVersion=2的独立恢复报告、覆盖全部四个新增域且零违规，备份摘要与原始创建时间匹配；不会接受只有`passed=true`的旧报告。SQL的`.metadata.json`保存原始快照时间，下载后文件mtime改变不能刷新备份年龄。

数据库备份不包含媒体对象。`backup-media.py`按恢复库生成的清单备份本地文件／命名卷及逐个OSS对象，并向独立空目标恢复、逐对象回读。数据库存在媒体记录时，发布必须同时提供数量及清单摘要匹配的媒体恢复报告；仅文件上传或归档自检不够。具体命令见 [备份与独立恢复](integrations.md#8-备份异地副本与独立恢复)。生产资源仍须实际演练，代码和本地验证不能代替生产恢复成功。

本机`backups/.backup-disabled`继续保留；生产独立配置恢复条件。常规应用回滚使用兼容版本，数据库采用兼容迁移及向前修复；不要直接让旧模拟版本读取真实资金状态。

## 试点运行边界

继续使用Java、Python、MySQL、Redis和Compose。内存中的准入、部分SSE及会话派发有单进程边界，不能直接增加worker或副本并假定全局限制成立；扩容前根据实际瓶颈验证。当前本机并发测试不等于生产容量承诺。

不抽佣，不做商户自助进件、骑手资金结算或自动派单。业务规则稳定后可以冻结功能范围，但依赖安全更新、供应商接口变化、证书密钥维护、故障修复和恢复演练仍属于正常维护。

## 发布顺序

1. 提交并同步代码，取得本次远端CI／安全结果。
2. 取得适用的备份与恢复证据，再构建、扫描并固定应用镜像摘要。
3. 使用目标配置执行迁移、部署及健康／角色验收，保存发布回执。
4. 对启用的外部服务执行 [真实接入验收](integrations.md#11-执行生产服务验收)，最后由运营负责人确认试点放量。

本地启动可使用`start.ps1 -Build`；它会启动数据服务并对日常数据库执行迁移，不能当作只构建镜像的命令。固定镜像生产发布按 [发布与回滚](integrations.md#9-固定镜像发布与回滚) 执行。
