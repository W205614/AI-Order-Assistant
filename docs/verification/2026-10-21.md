# 2026-10-21 校招演示与稳定性验收

本轮目标是完整、可复现的校招演示和单机恢复能力。支付及退款均为模拟，未接入真实资金、外部配送或公网运营。写入式角色与模型验收使用独立的 `ai-order-role-uat` / `19090`；演示初始化使用 `ai-order-demo` / `19092`，没有向日常库写入验收订单。

## 修改依据与结果

| 发现 | 修复 | 验证 |
|---|---|---|
| 首次部署只有基础单店数据，多角色演示需手动准备 | 独立演示命令，通过已有业务 API 初始化两个校区、两家店和完整协作角色 | 全部角色可登录；重复初始化资源数量不变，人工修改店名保留，订单数仍为零 |
| Docker 重启时备份与 MySQL 同秒启动，备份日志报无法解析 `mysql` | 最长 120 秒就绪等待；失败后 30/60/120/300 秒顺序退避，之后每 300 秒重试 | 隔离实测数据库缺席后启动、备份重启、失败状态保持及 30 秒重试恢复均通过 |
| HTTP 会话失效后，既有事件连接未重新校验 | 两套事件通道在每批推送前复用原会话认证，异常即关流 | 退出、改密、停用、商户停用、到期、权限变化及认证库异常的定向检查通过 |
| 用户编辑期间发生事件刷新，返回较晚的订单响应可能替换反馈表单 | DOM 提交前再次检查编辑状态，保留未确认游标，离开编辑区后补刷 | Chromium 确定性复现先失败，修复后 3 项检查通过；真实反馈与售后链路复测通过 |
| 加购和真实报价已经完成，再请求模型整理文字导致单轮预算耗尽 | 严格的“加购并报价”指令满足全部成功、报价有效、上下文和数量金额一致时直接生成报价说明 | 离线预算边界回归及限额真实模型定向复测通过；未提高正常单轮额度 |

备份原故障在修改前已按原有 300 秒重启逻辑自行恢复；时间与日志支持启动/DNS 竞争的解释，并非持续凭据错误的证据。新逻辑改善恢复过程，不能据此推断所有主机故障均可自动恢复。

## 五角色体验

最终扩展角色脚本 **25/25 通过，浏览器 JavaScript 错误为 0**。桌面操作后检查五类角色的 `390×844` 手机视口，均无水平溢出。

| 角色 | 已验证的主要操作 |
|---|---|
| 顾客 | 跨店加购与优惠报价、确认及模拟支付、自提与配送、数量退款、反馈与查看回复、申诉及平台处理结果；刷新与分页 |
| 店主 | 配送规则回填、保存后面板保留、接单备餐、数量退款处理和反馈回复；所属校区保存 |
| 店员 | 接单至备餐；隐藏店主配置，直接调用配置及库存接口被拒，跨商户请求被拒 |
| 平台 | 刷新配送任务、查看异常与订单校区信息、改派接续骑手、反馈回复、售后争议裁决 |
| 骑手 | 抢单、竞争抢单失败后归属不变、取餐、异常报告、接续配送、错误送达码后纠正并完成 |

校园浏览器流程 **18 项**通过，包含双券分摊、部分店铺不可提交、独立取消、预约容量场景、自提码、配送码、反馈和分页。HTTP 角色隔离 **34 项**通过。新增功能测试复用既有场景，没有重复运行无关的大规模压测。

重复确认返回相同结算；重复支付仅一条支付流水；重复数量退款返回同一售后；重复取消只退剩余金额一次。对应账务为 1 条支付、2 条不同操作的退款，操作键不重复。最终 **13 项数据约束均为零异常**，涵盖库存、预约容量、退款上限、支付退款汇总、单位金额分摊及孤立明细。

初测对应源码 `9474ae0`，报价终止条件修复对应 `e17a2a8`。追加授权独立计账，原 `recruit20261021` 账本及失败报告保持不变，复测使用 `recruit20261021-retest1`。总计 21 次请求尝试、214126 单位；单位为请求 UTF-8 字节与输出预留之和，**不是供应商计费 token，也不是金额**。
