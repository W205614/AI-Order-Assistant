## 工程与安全

- 修复 Agent Java 回调源限制、网络错误公开信息和校园回包中的异常字符串；保留明确的业务消息及预算分类。
- 状态变更的地图限流、微信授权发起改用 POST，草稿 GET 保持只读；同源页面及实际调用方同步。校园目录的租户作用域保留实际嵌套恢复行为。
- 预约时段不能跨过普通或隔夜闭店边界；准确结束于闭店时刻允许。
- Okio JVM 升至 3.4.0，实际嵌套依赖仍为 140 项；新 SBOM 在打包前生成，避免打入过期副本。
- Caddy 升级到上游 jose/v4 和修复的 crypto；MySQL 保持 8.4.13，使用原 Oracle 信任公钥验证的五个固定 OS RPM 及修复的 gosu 依赖。Redis 保持 8.10.3，更新系统包。Prometheus、Alertmanager 补齐同一 crypto 修复。
- 扫描门槛覆盖 UNKNOWN、LOW、MEDIUM、HIGH、CRITICAL，包括没有 FixedVersion 的未解决项；没有通过 ignore-unfixed 或忽略规则清零。

启用并实际执行五种语言 CodeQL、Dependabot 与 Secret scanning。首次 CodeQL 21 项、Dependabot 4 项；修复后远端开放列表均为 0。微信账单 SHA1 为单独获用户接受的协议例外：官方接口仍要求 [SHA1 校验](https://pay.wechatpay.cn/doc/v3/partner/4013080597)，系统另外保存 SHA-256 指纹。告警 #9 已保留原始证据并按此单项例外处理，**不是算法已修复**。

已发布应用镜像的全级别基线有 50 条组件告警；新候选和 d73d1cd 工程 CI 的 7 张部署镜像、23 个解析服务条目，均已实际扫描为 0。工具为固定 Trivy 0.75.0，数据库 UpdatedAt 2026-11-10 06:59:14 UTC。这个结论限于工具实际支持并识别的包，不代表绝对不存在漏洞。d73 安全工作流的源码材料门禁仍因旧锁而失败，未据扫描通过上传运行镜像；后续必须核验更新后的完整工作流。
