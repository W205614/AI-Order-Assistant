# 过度防御性编程修正与复核

本轮基于 `b95ccfe`，修正六项代码审查发现。范围为原单店工具、共享模型客户端、菜单缓存和分页入口；校园交易的权限、过敏约束、库存、价格、幂等及版本校验保持有效。

| 问题 | 修正后的行为 |
|---|---|
| 后端异常响应被当作空业务结果 | 在 Java HTTP 响应边界使用已有 Pydantic 校验菜单、订单和偏好结构；异常返回 `java_invalid_response`，合法空列表及未设置偏好正常返回 |
| 通用文本白名单误拒绝 | 长度由各字段的模型约束负责；FAQ 支持 500 字，正常 Unicode 名称和标点可用，既有疑似指令注入检查保留 |
| 内部错误被误报为外部故障 | 仅转换已知模型、网络及业务异常；未知程序错误交给已有请求入口处理，停止把它们归为模型或网络不可用 |
| 缓存兜底隐式重试数据库 | 缓存异常仅影响缓存操作；查库失败直接传播，写缓存失败不再次查库，缓存异常记录安全分类日志 |
| 非法分页被静默修正 | 缺失参数仍默认 `page=1,size=30`；显式越界返回 HTTP 400 |
| 已验证内部参数重复检查 | 草稿 handler 直接使用 Pydantic 验证后的必填参数，移除重复判空、字符串清理和请求消息长度复查 |

本地验证：Python 共 126 项，123 项通过，3 项需要隔离 Redis 的测试未在本机此次运行；Java 针对性测试 12 项全部通过。新增回归覆盖异常响应与合法空结果、256/500/501 字边界、正常 Unicode 文本、内部异常传播、缓存读写故障与数据库单次失败，以及真实 MVC 分页绑定和错误响应。未调用付费模型。

复核原则：网络服务之间的输入校验、交易执行时的可变状态复查、有界超时/并发/额度、缓存故障时查库，均有明确边界和业务依据，不因出现多层校验就移除。远端完整集成、浏览器与镜像扫描结果以对应提交的 GitHub Actions 为准；代码测试不代表公网、真实支付或备份恢复验收。
