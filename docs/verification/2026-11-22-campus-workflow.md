# 2026-11-22 校园点餐完整清单验收

本轮把顾客、商家、骑手、平台和 AI 的改动纳入同一个本地候选。Git 基线为 6b70be7，候选包含当前工作区的修改。Gateway 使用 Java 21，实际连接独立 MySQL 8.4，并由 Flyway 迁移至 V11。Agent 使用独立 Redis 和受控 HTTP 模型端点。用户、订单、地址和支付记录均为测试数据。

## 清单验收

| 使用流程 | 候选验收结果 |
|---|---|
| 首次访问和选餐 | 游客可以匿名查看公开校区、店铺和菜单。登录后按账号恢复校区和履约方式，菜品可跨店搜索，支持营业筛选和按履约方式比较费用及预计时间。普通交易接口仍要求登录。 |
| 结算、付款与弱网恢复 | 核对各店费用和优惠。配送费在确认前变化时展示新旧价格及具体原因，购物车保留。浏览器测试让服务端建单后丢弃响应，刷新后成功用同一幂等键取回同一笔订单。模拟支付及受控渠道状态恢复均通过。 |
| 取餐、历史、复购、售后 | 当前订单有快捷入口，并按店展示进度和交接信息。历史可按店铺、日期和状态筛选，列表默认只取摘要，展开才取详情。复购先核对现价和可用商品，退款先核算按实付分摊的预估金额。提交售后后保留该订单的跟踪入口。 |
| 商家和店员 | 已支付新单可进入待接单队列。店员按待办顺序处理预约、备餐和取餐。支持规格搜索、标记售罄和恢复可售。店主的自提备餐预计区间独立于配送规则。 |
| 骑手和平台 | 骑手区分可抢、本人进行中和历史任务。异常可选原因并补说明。平台待办集中显示履约异常、售后和渠道退款，可打开指定订单、记录处置说明并改派。原骑手在改派后失去收货信息访问权限。 |
| AI 和跨角色体验 | 预算与聊天方案使用 Java 核算结果，支持优先同店或预计更快。旧请求可以省略偏好参数。同名或规格歧义先澄清，用户明确点击后才加购。验证了过敏安全、账号切换、推送期间保留编辑和五个角色的移动端布局。 |

## 测试与候选身份

- Java 定向回归 102 项通过。最终校园交易、推荐边界和 Flyway 套件 75 项，支付和对账定向套件 27 项，失败、错误及跳过均为 0。
- Chromium 隔离浏览器流程 105 项通过。校园交易及受控推荐 33 项，多角色体验 32 项，过敏约束 40 项。三份报告均无页面脚本错误。
- Agent 校园回归 45 项通过。浏览器接口夹具另外覆盖响应丢失、重复点击、支付会话恢复、编辑期间推送、分页、权限和账号切换。静态脚本、CSP 和格式检查通过。
- 访客目录的匿名请求和旧推荐参数在初测中暴露了兼容问题。最终串联复验确认匿名浏览正确放行、原交易端点保留鉴权，并且省略推荐偏好的请求可以正常获得方案。
- 本机证据保存在 .local/experience-complete-20261122/。三份最终浏览器报告为 campus-final.json、roles-final.json 和 safety-final.json。候选 JAR 中 37 个静态或 SQL 文件逐项匹配工作区，JAR SHA-256 为 b0633d1202eb2be6246ed6467150635bc86eae921671add5399f4642db48a28d。

## 验收范围

按真实用户任务顺序进行浏览器复验，使用独立账号和模拟支付。渠道回归使用受控支付端点。日常库和公开部署没有参与本轮试验。预计时间取店铺配置区间，动态估时的实际样本验证及真实渠道试点依原清单前置条件进行。
