## 功能与本地验证

- 售后、反馈接口新增有界的待办/历史分页，沿用原数组响应与无参数默认行为。管理页面默认每页50条待办，顾客反馈默认显示全部；切换范围回到第一页，刷新保留范围和页码。
- 独立测试环境使用本次重建的同一组应用镜像，向目标列表加入225条更新的历史记录。较早的待审核售后、待回复反馈仍在待办中；商户与平台历史第一页、第二页无重复，顾客可在第五页找到较早的回复。模拟退款审核、反馈回复完成后，事项离开待办并可从历史访问。
- AI 工程流程使用受控 OpenAI 协议响应，实际经过 Agent、Java 工具、数据库与浏览器。明确“两杯”后，购物车目标数量为2，页面显示同步后的店铺、完整商品规格及数量；“核对购物车”仅定位页面，没有创建订单或支付。
- 要求“三杯”但工具返回1时，数量门槛拒绝该商品写入，返回 `needs_input/cart_quantity_mismatch`；购物车不变，本轮旧报价不再提供确认入口。浏览器刷新完成后，澄清提示与按钮行为均通过检查。
- 日常环境的顾客、店主及平台真实登录、页面和分页接口通过；五服务健康检查通过，Prometheus 的 Java/Agent 抓取目标均为 up。日常19张业务表的重建前后校验值一致，认证登录/退出产生的会话变化不在业务表校验范围内。
- 新 Agent 镜像内部的38项校园测试通过。此前本地57项 MySQL 集成测试、38项校园 AI 测试和相关浏览器检查，以及该应用提交的完整 CI，分别提供回归证据，数量不相加为一个测试集。

本轮没有调用付费模型。受控响应验证工程行为，不能替代真实模型面对陌生表达的理解效果评测。原始 JSON、截图与日志位于本机忽略目录 `.local/deploy-20261031/`，不随仓库分发。

## 构建方式与限制

首次按仓库 Dockerfile 完整重建，在安装锁定的 `pydantic_core==2.50.1` 时失败，当前包源没有提供可安装的发行文件。该结果仅说明本次本地构建所用包源的情况，不代表所有环境均无法构建。

本地部署采用已核验运行层重建应用：Agent 重新复制当前应用与评测源码，运行层54项锁定依赖版本全部一致；Java 使用本机工具链重新打包 JAR 和 SBOM，新旧 SBOM 的118项组件名称、组及版本一致。没有降级依赖、修改锁文件或将旧应用代码当作新版；两个应用镜像的 revision 均为本次应用提交。

这次本地部署不构成全新环境完整安装依赖成功的证明。已有部署恢复运行可执行 `.\start.ps1`；应用源码更新后需重新构建，新环境还需确认镜像与锁定依赖可取得。

## 清理与停止

验证后移除6个独立测试容器、4个测试卷、6个测试网络，另移除日常环境成功退出的一次性迁移容器。旧应用镜像标签已由新镜像替换，保留当前项目与共享镜像，没有执行全局 prune。临时构建副本和 Python 字节码共2个目录移入 Windows 回收站，未清空回收站。

截至本轮结束，五个日常容器全部停止、无 OOM；四个业务卷的名称与创建时间不变，六个日常网络保留。本机备份和恢复继续停用，保留停用标记与状态，本轮未生成数据库备份。该状态是本轮检查点，后续启停和配置以实际环境为准。
