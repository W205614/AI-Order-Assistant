# 校园过敏确认、购物车意图与超时分类修复

起始提交：`aea1f7f0ec5da067b5b4a88176a72f39ccd0e4d3`。本轮修复 README 核对暴露的三处实现缺口，没有数据库结构迁移。

## 问题与实现

1. 校园页面缺少过敏确认控件。现在菜单上方可选择花生、鸡蛋、麸质，并按当前店铺确认或清除临时约束，复用 `/order/safety-context` 和单次商户请求头。待确认状态会提示逐店处理，清除不删除长期偏好或购物车快照。当前页面内未提交选择按店保留，刷新、聊天返回和保存失败不覆盖；保存按店串行，切店再切回也不能并发提交旧约束。未提交或正在保存时，阻止页面继续发起加购、复购、购物车对话和报价。
2. 校园工具原先只看消息中是否出现“加购/准备购物车”，说明、提问、引用等可能误触发。现在按完整命令与限定子句白名单校验，拒绝发生在构造 Java 客户端之前，返回 `cart_authorization_required` 和重述示例。移除“加购＋任意文本”分支，“加购按钮在哪里”与含糊短句要求重述；保留“把奶茶加入购物车”“把刚才的组合加入购物车，每样一份”及既有推荐组合指令。
3. `ConnectTimeoutException` 继承 `SocketTimeoutException`，校园接口原先将其误报为读取超时。现在两套对话均将连接超时报为 `503 / AI_UNAVAILABLE`，读取超时报为 `504 / AI_TIMEOUT`，普通 I/O 连接故障和显式 Agent 504 的既有处理保留。

## 复现与复验

先保留失败，再验证修复：旧页面因找不到校园约束控件失败；原 Python 规则在只读与问句子场景中实际放行；校园连接超时测试原先预期 503、实际 504。独立审查还发现并修复了未保存选择被刷新覆盖、保存失败丢选择及同店旧请求覆盖新保存的窗口。
