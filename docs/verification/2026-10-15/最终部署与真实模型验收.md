# 最终部署与真实模型验收

2026-10-15，在 `915dc3b` 基线上修复本轮发现的问题。真实模型、业务写入和故障注入使用独立的 `ai-order-clean` 数据库与 19090 端口；正式 9090 入口只做登录与只读验收。最终应用镜像先在隔离环境验证，再提升到正式本地六服务部署。没有修改数据库结构，没有接入真实支付。

## 本轮发现与修复

1. **确认后重复澄清**：顾客已在页面逐店确认，发送“我已在页面确认过敏约束，继续推荐”仍被当作新的过敏声明。现在只对受支持的完整确认引用复用该顾客、该店有效且已确认的上下文，不写入或续期；待确认、过期、跨顾客、跨店和新增约束仍需确认。单元红测和真实 MySQL 回归保留。
2. **模型误解安全快照**：首次真实模型运行在第六轮失败，模型把安全商品的 `safetySnapshot=花生` 误认为商品含花生。该字段实际保存顾客的避敏约束。现在仅在模型工具消息视图中改为 `appliedCustomerAllergens` 并解释含义；递归复制数据，不改变 Java DTO、购物车和原始报价对象。新增回归验证搜索、推荐、购物车和原始报价契约。
3. **聊天失败后的安全状态滞后**：Java 可能先记录待确认，随后 Agent 请求失败。页面现在使旧报价失效并尝试同步菜单与安全状态；同步也失败时提供刷新入口。此故障场景使用实际 Java 状态与浏览器响应注入验证，不冒称真实提供商故障。
4. **未保存选择缺少返回入口**：跨店、跨校区保留的未保存选择会阻止后续操作，但旧提示没有指出店铺。现在列出店名及来源校区，可前往确认或放弃本页未保存选择；保存中不能放弃。放弃不删除服务端约束或购物车快照。
5. **迟到导航覆盖当前选择**：从待处理列表跳转后，旧店铺或地址请求可能覆盖用户随后选择的校区/店铺。导航版本与来源校区共同检查各异步阶段，手动选择使旧目标失效，过期错误也不覆盖当前提示。保留先红后绿的延迟响应验证。
6. **旧手动报价清除新报价**：旧手动请求返回时先赋值全局报价，发现条件变化后又清空，可能破坏较新的助手报价。现在先校验请求版本再应用；回归检查最终确认请求仍携带较新真实 Java 报价的标识，确认接口被测试拦截，没有为此创建订单。

上一轮已收紧购物车完整写指令，并统一连接超时 503、读取超时 504；本轮对这些行为再做模型/回归检查，不把未支持的自然语言写法宣称为全部支持。

## 真实模型与页面链路

使用显式配置的真实提供商、自动工具选择、独立顾客和三个店铺。店铺位于来源校区并明确开放目的校区配送。安全商品为米饭与奶茶，同时设置同名冲突商品、含花生商品和未核验商品。测试顾客领取店铺满 12 减 2 与平台满 15 减 3 券。

最终场景顺序为：预算内跨店推荐；解释加购操作、提问及引用第三方指令均不写购物车；声明花生约束使三店进入待确认；通过实际校园页面逐店确认；引用已确认上下文继续安全推荐；明确授权将组合各加一份；在实际校园聊天表单查询优惠并获得可核对的 Java 报价。

预期账单：商品 20.00、包装 1.50、配送 5.00、店铺优惠 2.00、平台优惠 3.00，实付 **21.50 元**，在 25 元预算内。模型不自动创建结算或支付；页面最终报价保留由本人点击的确认入口。

首次失败与修复后完整运行分别报告；不清除首次失败后声称一次通过。单次链路成功不代表其他模型、输入或采样结果均可靠。购物车授权门槛仍不逐项绑定模型选择的商品与数量，顾客需核对；模型对话使用有限近期上下文，不能承诺无限多轮指代可靠。

首次共 6 条对话，9 次提供商调用，21,598 输入 / 5,364 输出 token；修后完整 8 条对话，19 次调用，53,590 输入 / 6,531 输出 token。合计 14 条对话、28 次调用、75,188 输入 / 11,895 输出 token；以上为提供商报告值，没有据此推算费用。最终八条回复均人工通读，金额与下一步一致；第八轮从真实校园表单提交并应用结构化报价，未注入报价或确认按钮，没有新增结算。三个店铺均通过实际页面控件确认过敏约束。

首次运行的一条回复曾在句中结束，未保存提供商 `finish_reason`，不能判定截断根因；最终八轮未观察到该现象，当前接口也不提供通用截断判定。这不影响 Java 结构化报价复核，但不能据此承诺所有自然语言回复完整。

公开顾客全图与账单局部图是在模型链路完成后重新登录，使用其已准备的购物车再次手动请求 Java 报价截取；只有地址选择框被窄范围遮罩。此截图步骤额外模型请求为零，原始模型表单应用报价的完整证据留在本地。

## 部署、证据与边界

应用构建没有挂载源码。比对网关 JAR 内校园 JS、HTML、CSS 与工作区的 SHA-256，并比对 Agent 校园模块；正式容器使用隔离验收的相同应用镜像。升级前保留数据库备份及校验、旧应用镜像归档。正式数据卷保留，测试清理只作用于本轮独立项目。

验收后移除本轮 `ai-order-clean` 四个测试容器、三个测试数据卷、网络和两份测试镜像标签；正式项目保留六个运行容器及两份应用镜像标签，未对其他项目或全部 Docker 缓存执行清理。

原始模型回复、工具结果、浏览器截图、失败日志与账号 fixture 保存在被 Git 忽略的本地证据目录；公开结果只包含去除凭证及地址细节的摘要。README 截图使用测试数据；公开图片不展示完整地址。最终提交的 CI、安全扫描以该 SHA 的 GitHub Actions 为准，顶部徽章不能代替精确提交验证。

本轮不重复历史迁移恢复演练、公开域名 TLS 或长期运行验证。性能只报告本地有限负载样本，不代表最大容量或长期 SLO。视口检查不等于真实手机设备兼容性验收；菜单安全标签不保证后厨交叉接触安全。支付、退款与优惠成本仍为模拟业务记录。
