# 校园平台代码审查与运行复验

2026-10-15，基线 `b525b92`。代码、功能、用户体验由三个独立代理分别检查，主代理复核并完成部署。本记录与修复代码、八个依赖分支的合并结果一起提交；最终远端 CI 以交付提交的 Actions 为准。首次扩展的迁移及恢复演练见 [校园平台验收](校园平台验收.md)。

## 已修复的问题

- 商家补货到人工库存上限后，原取消、支付超时关闭和制作前退款无法回补。人工调整仍保留上限，预留释放按整数存储边界处理。
- 全额优惠的零实付商品分次退款被支付状态提前阻止。现在同时按原金额和逐份可退状态核验，不允许多退或重复回补。
- 事件游标、同菜品默认/命名 SKU、券活动与预约容量存在锁序反转。使用 MySQL 等待图与 InnoDB 死锁记录复现后，统一父菜品、SKU、券活动、券、预约和提交前事件的顺序。
- 按订单范围更新商品单位会持有尾部区间锁，阻塞另一结算插入。改为枚举不可变标识、逐主键当前读和精确更新，保留 RR 隔离级别。
- 等待退款事务后，取消仍可能读取 RR 旧快照并重复回补。补偿现在使用锁定后的实际单位状态；同幂等键并发退款返回同一申请。
- 商家校园队列缺少商品、备注和预约明细，旧队列还显示被保护接口拒绝的操作；所属校区刷新后回显错误。已补齐明细、回显、刷新和新旧订单入口区分。
- 骑手取餐缺少可匹配订单标识，平台展示已完成任务改派、取餐后释放等无效操作。已补标识并按状态展示操作。
- 顾客结算只能看到前 20 份。新增分页与加载更多，事件或手动刷新保留已加载历史记录；旧入口的校园订单引导到聚合页面。
- 权限测试依赖三秒静默读取超时，心跳会延长等待并触发外层超时。改为绝对三秒观察期限，保留本人事件必须收到、他店事件不得出现及外层五秒断言；连续心跳模拟在 3.009 秒退出并关闭连接。

以上并发回归要求实际出现数据库锁等待，再验证双方成功或正确回滚；没有添加业务重试、修改隔离级别或放宽金额、库存与权限断言。

## 依赖与部署

合并八个 Dependabot 分支：两个 Actions、CycloneDX 插件及五个 Python 依赖。`jsonpatch 1.35` 要求 `jsonpointer >=3.2`，额外固定到 `3.2.1`，避免直接合并后依赖解析失败。实际版本保存在依赖文件和结果 JSON 中。

网关和 Agent 均由仓库 Dockerfile 构建，网关使用 CycloneDX 2.9.3 生成 SBOM；复用本机 Maven 缓存，不宣称空缓存构建。9090 部署实际 JAR SHA-256 与隔离验收镜像一致：

正式六服务运行，四个核心服务健康，五个页面返回成功，网关与 Agent 监控目标均正常。更新前后 33 用户、7 商户、54 订单、56 明细、库存合计 1349 及所选订单财务/菜品库存字段指纹一致；不表示全库逐字段比较。

## 清理与恢复保留

仅清理本项目：移除四个隔离容器及网络、中间构建镜像、旧应用镜像和重复测试标签；最终保留六个正式容器与两份应用镜像。未清理其他项目、共享基础镜像、业务卷或测试卷，没有全局 prune。

旧部署和中间应用镜像先保存为本机 `.local/audit-cleanup` 下的归档，核验归档 SHA-256、OCI 标识、运行配置、平台及层文件后再删除镜像；数据库备份位于 `.local/audit-live-backup`，此前升级前数据库备份及 Git bundle 也保留。归档校验结果见 JSON。涉及数据库结构回滚仍需配套原版本数据库备份，不能只恢复旧镜像。

## 验证边界

未验证新增校园协议与真实模型提供商的完整对话、真实支付和商户资金结算、公网 TLS、屏幕阅读器、全部移动浏览器、长期 SLO 或最大业务容量。已验证的固定工具权限、Java 真实报价和手动交易可用性不替代这些验证。
