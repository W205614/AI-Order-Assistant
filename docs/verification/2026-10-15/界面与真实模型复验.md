# 界面与校园真实模型复验

日期：2026-10-15。基线为 `79a56bda6f6c3c67ea6c646d16e173794784501e`，本次继续使用 Java 单体、Python Agent、MySQL、Redis 和原生页面。支付、退款仍为模拟；模型没有确认、支付、售后审核或骑手操作工具。

## 界面与使用问题

参考 [Taste Skill](https://github.com/Leonxlnx/taste-skill/tree/f624f37a8c650b9cc550253104925efe4c8de246) 的 Redesign、Minimalist UI 指引，统一首页与五个工作页的排版、导航、表单、状态和键盘焦点。校园页按选店、购物车、报价、AI 搭配与订单组织；商户和平台优先显示日常校园业务，配置逐步展开。没有引入前端框架、外部字体或虚构销量、评分、商品图片。

发现并修复：

- 首页 `/` 转发到 `/index.html` 后被鉴权拦截；现已公开对应 GET 静态入口，业务接口授权保持原规则。
- 登录后的附属接口失败会把用户留在登录表单；现保留账户与退出入口，并可重新加载工作区。
- AI 报价曾只出现在文字中；现返回真实 Java 报价结构，核验目的校区、地址、履约方式、有效期、购物车行及版本后，展示账单与本人确认按钮。
- AI 请求或后续刷新期间修改优惠，旧响应可能恢复旧选择和报价；现贯穿异步过程检查版本，过时结果不会恢复确认按钮。

## 真实模型与修复过程

提供商为 `https://api.deepseek.com`，实际配置模型为 `deepseek-v4-flash`，使用普通用户消息和自动工具选择，没有强制模型调用指定工具。默认隔离 Compose 配置会清空密钥；最初两次无 usage 的降级请求仅用于定位配置问题，不算真实模型测试。

真实 API 验证分三段，保留失败记录：

1. 两轮基线：推荐能取得真实组合和优惠报价，但后续“按刚才推荐加入购物车”丢失上下文，未完成加购。
2. 六轮修复后验证：推荐、已领券查询、同名商品澄清、不可服务校区和交易权限边界通过；连续准备第二件商品时仍返回业务错误，随后触发既有保守预算。该轮没有算作完整成功。
3. 两轮定向复验：补充逐商品版本与目标数量的工具协议说明后，普通连续对话成功准备两家店各一件商品，并返回真实双券报价。旧失败 trace 没有参数，无法证明是否误用了另一商品版本，因此该原因仅列为推断；确定事实是补充协议后对应流程通过。没有提高模型预算，也没有自动忽略版本冲突。

校园助手新增按用户、校区、地址和履约方式隔离的短期文本历史，最多三轮、十五分钟过期。历史只辅助理解指代，本轮仍重新查真实商品、券和购物车。当前消息必须明确授权加购，否定和只读指令不能触发写入；Java 再核验商品服务校区、本人地址、安全约束与版本。Redis 写历史失败保留已完成的业务结果，避免让已成功加购的请求变成 500。

API 三段共十轮用户对话、二十七次提供商请求，提供商报告输入 70,719、输出 9,454 tokens，包含失败定位；这不是费用估算。浏览器真实请求另行记录，不混入 API 段计数。

## 并发审查

新增加购适配器最初在锁用户前读取商品与地址，可能提前建立 MySQL REPEATABLE READ 快照。并发修改购物车在锁等待期间提交后，后续普通读仍可能看到旧版本，导致旧请求覆盖更新。

确定性数据库回归通过 `performance_schema` 确认真实锁等待：修复前旧版本被接受，测试失败；修复后在事务任何普通读前锁用户，旧版本被拒，并发写入的数量、备注及新版本保持。相关三项真实 MySQL 测试通过。没有改低隔离级别、吞掉冲突或放宽断言。

## 验证与交付边界

Java 全量九十二项通过，零失败、错误、跳过；之后新增的并发修复及相关三项 MySQL 测试再次通过。最终 Agent 镜像内 Python 七十项通过。原单店二十三个、校园四角色十八个浏览器业务检查点通过。

响应布局检查覆盖首页、五个工作页及登录后四种角色，宽度为 390、768、1440。另检查错误登录、加载恢复、表单名称、键盘焦点、展开配置与手机溢出。加载失败与异步改券演练使用显式客户端故障注入；真实模型路径检查实际 provider 结果、持久报价、21.50 元账单、页面校区/地址/优惠一致以及购物车和结算记录未被只读请求改变。最终结果与镜像证明见 [机器可读结果](ui-model-results.json)。

浏览器共追加两轮真实报价请求，第二轮在最终无源码挂载镜像中执行：207 个 UI 检查点通过，脚本错误为零。人工检查手机回复中使用店名、商品名、金额和操作说明，没有版本号、UUID、工具字段或 Markdown 星号。API 与浏览器合计十二轮真实用户对话，不包含前置密钥配置失败请求。

最终验收使用不挂载源码的镜像；核验 JAR 中静态资源与工作区一致，Agent 校园模块与源码一致。正式升级前保存数据库备份和旧应用镜像归档，校验 SHA-256、归档 manifest 及层存在。此次没有新增数据库迁移。清理仅针对本项目测试容器与已确认不用的旧应用镜像，保留数据卷、回滚归档和其他项目资源。

本机正式入口 `http://127.0.0.1:9090/` 及五个角色入口均返回 HTML，四个核心服务健康，两个 Prometheus 目标正常。隔离环境十三项数据库不变量违规数均为零。最终只保留本项目六个正式服务和两份应用镜像；正式应用镜像、JAR SHA-256、回滚归档 SHA-256 及清理后清单记录在上述 JSON 中。

这些结果证明所列测试数据和当前提供商的可行链路，不代表模型回答可靠率、所有表达方式、全局最优组合或长期服务指标。未现场验证提供商自身故障、公网 TLS、长期 SLO 或最大容量。自提现规则仍要求店铺开放所属校区服务并满足其起送门槛，页面已说明该限制。最终提交的完整功能与安全 CI 以对应 SHA 的 GitHub Actions 结果为准。
