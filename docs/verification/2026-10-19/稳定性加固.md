# 个人维护版本稳定性加固

2026-10-19，基于 `e3525c2` 实施。当前版本继续定位为单机、可控试用，支付和退款仅为模拟。最终交付以本记录所在提交的 GitHub CI 和安全扫描为准；以下本地证据不替代生产容量或长期可用性证明。

## 修改与边界

- 保持 MySQL REPEATABLE READ 和既有资源锁序，确认结算使用锁后当前读核验商品、商户、配送规则和优惠。套餐版本变化先拒绝，避免读取新增低 ID 组件时引入反向锁序。
- 复购首次读取前锁用户；购物车更新同时核对用户及版本。每小时最多清理 500 条过期超过 24 小时、未消费且没有结算引用的报价。
- 校园结算的 `PaymentGateway` 只提供本地模拟 payment/refund/query，复用现有表；业务权限、金额与幂等仍由 Java 控制。没有新增真实支付或回调，未来外部调用必须单独设计事务外编排和对账。
- AI 每轮预留最大预算，结束按累计保守估算结算，原子返还未用部分。保留原 Redis 日额度键和旧余额，跨 UTC 午夜仍结算原桶。结算故障保留预扣、暴露计数；没有调用真实模型。
- 校园准入改为每顾客 2、单进程总并发 8；平台共享日预算独立命名。两个聊天入口统一结果指标，工具失败不误报完成，审计写盘失败不遮蔽业务响应。
- 主备份校验、互斥锁、原子状态、可选额外副本、七份轮换和只读巡检可独立使用。复制失败也轮换已验证的主备份；失败重试退避五分钟。备份新鲜度、状态缺失、磁盘和指标故障进入告警规则，外部通知默认未启用。

部署前保存本项目容器/卷基线、Git bundle、旧应用镜像及 SHA-256。停止应用写入后生成一致升级备份，独立临时 MySQL 恢复及选定指纹比对通过：33 用户、7 商户、54 订单、56 明细、库存合计 1349；明细归属违规为零。当前日常库校园结算为零，校园交易正确性来自前述隔离 MySQL 用例。恢复脚本耗时 14.03 秒，只是本次环境的恢复样本，不是完整故障切换 RTO。

备份 SHA-256 为 `3c3221af5181d434ac4e9db621f2a641f5caad904600b9fb80e6142d342757b8`。恢复过程不挂载源卷、不覆盖日常库，结束后移除本次临时恢复容器。应用镜像首次构建遇到 Maven Central 两个依赖下载截断；保留失败日志后重试成功，没有放宽编译或测试门槛。

最终应用镜像使用 OCI revision 标记交付提交，更新时保留原 MySQL/Redis 容器及数据卷；交付同时核验健康、页面、监控目标、备份状态、关键指纹及最终 SHA 的 CI。敏感 SQL、私有日志和原始运行证据仅保存在被 Git 忽略的本地目录；运行结果以最终交付说明和该提交 CI 为准。

默认仍没有异机存储、外部告警接收者、真实资金或集群故障切换。可选额外目录只证明复制校验，不能自行证明独立故障域。并发上限适用于单进程，预算估算不等于实际费用；恢复指纹只覆盖选定字段，不能证明全库逐字段一致。
