# 2026-11-22 校园点餐体验验收

本地候选基线为 Git 提交 6b70be7。验收在独立环境完成，使用 Java 21、MySQL 8.4、Redis、Agent、合成数据和模拟支付。顾客端使用 Chromium 的 390 像素宽视口复验。顾客、店主、店员、骑手和平台管理员分别使用独立浏览器会话。账号和业务夹具由测试脚本准备，以下是按角色流程复验的结果。

模型调用指向仅在隔离网络运行的受控 HTTP 服务。浏览器发起聊天，实际 Agent 调用 Java 推荐或搜索工具，方案卡和加购接着走真实服务。真实模型服务和外部支付渠道不在本轮验收范围。

## 按角色复验

| 角色 | 验收结果 |
|---|---|
| 顾客 | 能比较配送费和时间、从手机入口直接打开购物车。不可用店铺仍留在购物车，可重新报价结算其余店铺。费用变动时能看到原价和新价。创建结算后原地支付，返回页面可以继续支付，跨店状态及取餐信息按店显示。 |
| 店主与店员 | 已支付的新单自动提示并进入待接单队列。预约按可备餐状态展示。店员可以标记或恢复本店校园规格，实物库存和改价权限按原规则校验。 |
| 骑手与平台 | 抢单前可见公开取餐点和目的校区。接单后可见合成地址及交接说明。上报异常后能看到待处理状态，改派后由接续骑手获得任务和收货信息，原骑手访问被取消。 |
| 使用 AI 的顾客 | 方案卡使用 Java 核算结果，同店偏好影响排序。聊天推荐保持购物车原状，明确点击后才整组写入。同名商品触发澄清。候选过期、库存变化、过敏规则和履约上下文由后端重新校验。 |

## 回归结果

- Java 目标测试 71 项通过，失败、错误和跳过均为 0。覆盖 Flyway V9 到 V10 继承自提门槛、历史数据保留、取餐点快照、售罄权限、报价更新和推荐过期。
- Agent 校园回归 45 项通过，包含候选数据来源、同名及规格澄清、显式加购授权。
- 三套隔离浏览器流程共 96 项通过，分别为校园交易及受控推荐 27 项、多角色体验 29 项、过敏约束 40 项。三套报告均无页面脚本错误。
- 浏览器接口夹具覆盖加购响应丢失、重复点击、编辑期间推送、分页与账号切换。静态脚本、CSP、事件订阅和格式检查通过。
- 本机原始报告与截图位于 .local/experience-20261122/。三份最终报告为 campus-browser-final.json、role-experience-verified.json 和 campus-safety-final.json。Gateway 候选 JAR SHA-256 为 4e802749f1f62f62b6d661585d7452efd33ae928fc536eef23532cf7e5e91aab。

## 复验后的改进判断

复验发现营业时间读取类型影响顾客页加载，已修复并重跑真实 MySQL 和浏览器流程。另将取餐码与送达码放到订单旁显示，并在进行中订单为空时增加历史入口，已复验自提与历史订单反馈。

接下来优先简化手机历史订单。21 笔关闭订单加早期记录的分页用例已通过，但历史列表展开后仍很长，反馈表单也会重复出现。建议每单默认只显示店铺、金额和最终状态，点开后再查看商品及反馈。其次是从用户需求验证午高峰预计时间。当前区间来自店铺配置，可用真实到店和取餐样本先确认哪些场景需要动态估时。
