# v0.1.4 发布验证范围

本轮在2026-11-12进行，用户授权提交推送修复、发布新版本并同步本机非生产部署，明确不追加模型调用。正式源码Tag、镜像manifest摘要、包装提交、CI及发布回执以 [v0.1.4 Release](https://github.com/W205614/AI-Order-Assistant/releases/tag/v0.1.4) 的最终记录为准。

## 变更

- 模型连接失败记录有限层数的异常类型、errno及固定原因标识，避免丢失底层诊断线索；不输出密钥、URL、请求正文、headers或原始异常文本。
- 默认OpenAI SDK传输的真实localhost HTTP/1回归覆盖多轮同连接、第三轮断连和已有一次有界重试的预算扣记。没有增加产品重试、备用提供商或关闭TLS验证。
- 纳入已审查的Java/Python依赖升级及Go1.27.4标准库安全修复；保持MySQL8.4系列，不采用跨主版本升级。
- Java及Agent版本统一为0.1.4，没有新增Flyway迁移、支付渠道或业务功能。

## 已有真实模型证据的边界

[完整补测](2026-11-12-ai-transaction-retest.md)在本轮发布前的Agent候选上完成，26项通过：AI搜索和准备购物车、Java报价、顾客确认、模拟支付、商家备餐、骑手配送及完成状态。该次4次模型请求、31,960保守预算单位，无连接错误或重试。原始候选镜像和原账本身份保持不变，不能改写成最终发布镜像的新调用结果。

发布流程核对候选与最终Agent的应用文件、依赖及运行层等价性，版本元数据和新增许可材料单列。Gateway在真实补测时为v0.1.3；新版Gateway的依赖变化依靠本轮Java、隔离交易/浏览器及运行检查验证，不把旧Gateway的模型集成证据扩展为新版逐字节相同。历史连接失败没有底层异常记录，具体物理根因仍无法追溯；本次修复提高后续诊断能力。

## 发布与本机验收

只分发Gateway、Agent两个已有公开GHCR应用包，目标平台Linux amd64，以完整源码SHA作为镜像标签。候选先完成实际分发依赖、原始通知和对应源码核对，再以固定摘要推广；发布后另做匿名拉取与隔离运行。CI、候选检查、匿名回拉及日常部署分别保留结果，未完成或失败的尝试不改写为成功。

本机升级通过原`scripts/release.py`备份、独立恢复、指纹及迁移门禁，保留业务卷、私密配置和媒体；升级前已生成一次性SQL恢复点，独立恢复V9、61表及16项数据不变量通过。自动备份仍禁用，一次性恢复点不等于开启周期备份。日常验收仅检查健康、页面及原有账号的代表性只读业务，不调用AI、不写合成交易，最终恢复五个日常服务停止状态。

本轮不验证真实微信资金、短信、OSS、高德、云环境、生产负载或其他CPU架构。旧Release/Tag、原模型账本及失败记录保留，不发布新的Maven应用包。
