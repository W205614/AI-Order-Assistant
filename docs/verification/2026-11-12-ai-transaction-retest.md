## 原因诊断及证据边界

上轮只有 `model_connection_error`、两次成功用量回报和三次尝试账本，没有保存底层异常链。**无法追溯并确定那一次具体是提供商、代理、TCP/TLS 还是本地协议错误**，不能把本轮成功当作历史根因证明。

实际正式镜像安装 OpenAI 3.42.0，默认传输为 httpx2 2.13.1，HTTP/1 开启、HTTP/2 关闭；原测试注入 httpx 0.28.1 的 MockTransport，没有覆盖默认传输。[官方 SDK 错误说明](https://developers.openai.com/api/reference/python)指出底层异常保存在 `__cause__`；本地安装源码及真实边界探针进一步验证了具体包装行为。

不调用模型的检查结果：

- 在相同容器网络中，DNS、三次已验证证书的 TLS1.3 握手均通过；三次复用连接的未鉴权 `/models` GET 返回正常 HTTP401。它们没有携带模型密钥、不调用生成接口，单列为非生成连通性探针，不计为模型生成尝试。
- 在无外网容器、仅 localhost 假提供商上，默认 SDK 的正常三轮工具消息、跨线程复用及闲置连接关闭后重连均成功。未复现正常第三轮 JSON 或连接池必然故障。
- 故意让第三轮服务端直接断开，可复现前两轮成功后 `model_connection_error`，底层为 RemoteProtocolError；故意非法本地 header 也能产生同一公开分类，底层却为 LocalProtocolError。两者都是受控夹具，不能冒充上轮的实际原因。

目前未发现需要修改 DNS、代理、证书验证或连接池的证据，未禁用 TLS 校验、替换传输或增加备用实现。
