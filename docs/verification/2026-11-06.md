# 2026-11-06 校园多商户试运营补全验收

本轮落实微信服务商合单、阿里云短信与 OSS、高德、云数据配置及运维接入方案。交付包含实际适配代码、V7–V9 迁移、角色页面、配置模板、接入与验收脚本。默认启动仍为 `SIMULATED` 支付和本地图片；启用真实渠道不会自动回退为模拟成功。

工程实现、本地契约验证与生产账号实联分别记录。**微信真实扣款、公众号授权、短信终端收件、生产 OSS／高德、云数据库 TLS、外部告警、异地恢复及真实模型效果尚未实联验收，状态为 `NOT_RUN`。** 接入所需资质、账号、权限、资源和步骤见 [接入指南](../integrations.md) 及 [脱敏模板](../../deploy/integrations.env.example)。

## 交付范围

| 部分 | 本轮实现 |
|---|---|
| 交易 | 单店与跨店共用持久化支付域；微信 Native／H5／JSAPI、公众号 OAuth、逐子单核对、验签解密、查单和关闭；未知结果保留并查询，渠道网络请求不持有业务事务锁 |
| 退款与资金 | 售后审核与渠道退款分离；待退款金额与件数占用额度，成功后记账；连续部分退款和配送费退款汇总；取消停止履约、只释放一次库存；晚付款进入退款并结束为 `REFUNDED`，不重开履约 |
| 优惠与运营 | 冻结收款商户、金额和优惠快照；平台联合优惠需商户明确参与且由商户承担；零元子单免渠道扣款；支付／退款任务、账单摘要与差异处理入口，禁止人工改渠道支付成功 |
| 用户服务 | 全角色验证手机号与密码找回、旧会话撤销；本地／OSS图片真实内容校验与按资源授权；数据库站内通知、SSE及有上限的短信任务；高德地址候选与骑行路线、骑手导航 |
| 页面与AI | 支付会话二维码／跳转／微信唤起及返回查单；处理中、未知、失败和服务关闭均明确展示；历史模拟记录保留标识；AI使用Java提供的当前能力与业务事实，资金操作仍由用户确认 |
| 云与运维 | 外部MySQL及Redis的独立身份、TLS与只读CA挂载；数据库后台任务；支付／退款／对账／通知指标；Alertmanager SMTP及通用Webhook；OSS备份回读摘要、独立恢复入口；固定镜像发布与兼容回滚 |

保留抢单及人工改派；没有增加自助进件、平台抽佣、骑手资金结算或自动派单。未增加消息中间件或拆分服务。

## 本轮修正的实际问题

- 官方微信SDK响应头查找区分大小写，而HTTP客户端会规范化头名称；补齐微信签名响应头的标准名称映射，并通过真实签名HTTP验证。
- 按官方接口区分未付款查单与付款成功字段、退款响应与退款回调字段；补齐合单子单`attach`、H5设备标识、逐子商户关闭以及包含秒的RFC3339期限。
- 修正渠道旧响应覆盖已支付／关闭状态、并发退款额度占用、第二次部分退款触发旧兼容流水唯一约束，以及晚付款退款没有终态的问题。
- 跨商户旧入口查不到订单时明确404，避免空查询500；找回密码接口可处理旧失效Cookie，其余入口继续认证；OAuth防止重复OpenID静默换绑账号。
- 新增验证码输入框造成旧浏览器选择器歧义，调整为明确字段；重建期间的瞬时断连保留失败日志并在稳定环境重跑，不将失败文件删除或改写成成功。
- 升级SDK传递的存在已知可修复高危问题的密码学依赖；安全结果经最终扫描确认。

初次失败及后续成功日志均保留；上表采用最终成功回执，并说明覆盖边界。
