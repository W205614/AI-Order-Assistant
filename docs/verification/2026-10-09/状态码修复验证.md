# Agent 状态码修复验证

日期：2026-10-09，北京时间。范围：修复连接 Agent 超时的状态码分类，不新增业务功能、不做性能优化。

## 问题与修复

原网关在 Agent 停止后，连续三次聊天请求分别返回 503、504、504。后两次约两秒结束，与客户端的两秒连接超时一致。

Apache HttpClient 的 `ConnectTimeoutException` 继承 `SocketTimeoutException`。原 `ChatController` 的通用 socket 超时分支将其误归为 `504 / AI_TIMEOUT`。新增位于该分支之前的连接超时处理，返回 `503 / AI_UNAVAILABLE`。连接拒绝和 DNS 失败仍返回 503；响应读取超时仍返回 504；上游显式 429、503、504 的语义保留。

这不是调整超时、限流或重试参数，只修正异常分类。

## 部署和恢复边界

用户明确允许只替换同名网关。使用 `docker compose ... up -d --no-deps --no-build --pull never --force-recreate --wait gateway`，未创建新的部署项目，未替换数据库、Redis、Agent、备份或监控容器，未删除数据卷。

原网关根文件系统只读且 JAR 未挂载，无法保留其容器 ID 原地替换应用。原镜像内容索引已缺失，无法直接添加旧镜像标签；部署前保存旧运行 JAR/SBOM，基于新运行镜像制作 `ai-order-assistant-gateway:before-status-fix-20261009` 回退镜像。它保留旧应用制品，不能称为原完整镜像的逐字节归档。新镜像摘要为 `sha256:84eefec0ab3b40071843fa77434c347a5ac499261b5fcf6b7c96b03356e82e66`。

部署前完成数据库备份并核验 SHA-256。测试商户最终停用，测试交易与审计保留。本地原始日志、JAR、备份和凭证位于被忽略目录，没有提交。

本轮未在本机运行会创建临时 MySQL/Testcontainers 的 Java 集成测试，也未进行性能或公网测试。真正响应超时的分类由真实本地 HTTP 客户端测试及控制器测试共同覆盖；未在正式容器中注入慢模型提供商。

## 回归入口

在 `java-gateway` 目录运行：

```powershell
mvn -B -ntp '-Dtest=ChatControllerFailureTest,AgentHttpClientTest,JwtUtilTest,DemoDataSeederTest,FlywayConfigurationDefaultsTest,SecurityConfigValidatorTest,FoodSafetyTest,UserPreferenceServiceTest' test
```

`ChatControllerFailureTest` 覆盖连接超时、连接拒绝、DNS 失败、响应超时和上游明确的错误状态；`AgentHttpClientTest` 验证真实 HTTP 成功、失败、空响应及已接受请求后的响应超时。
